# 按信任边界选择调查技术

本页把候选变成可回答的问题；先选当前不确定的边界，再读对应配方。示例均为方法对照，不是目标已有漏洞。实际运行、隔离和证据保留见 [执行与验证](execution.md)。
不设发现数、逐函数阅读量或“143 项全覆盖”配额；缺少注解、锁、DTO 或某条基线只能引出调查，不能代替边界证明，也不直接决定严重度。

| 当前疑问 | 先用的配方 | 应得到的区分事实 |
| --- | --- | --- |
| 输入最终被当成数据还是语法？ | 1：解释器与值 | 最终调用、参数位置、实际控制范围 |
| 主体能否操作这个对象？ | 2：控制与资源 | 入口、角色、资源、动作及实际生效的控制 |
| 早期校验是否被后续步骤改变？ | 3：响应最终语义 | 最终头、内容、来源与浏览器约束 |
| 顺序、并发或配置改变安全结果？ | 4：状态与配置 | 可达状态、可行交错、原子边界与部署条件 |
| 长度或对象在使用时是否仍有效？ | 5：原生边界 | 算术范围、容量、生命周期与调用契约 |
| 公告或反编译代码对应当前交付物吗？ | 6、7：依赖与谱系 | 实际装载身份、调用条件与证据缺口 |
| 手读后仍有一个精确未知量？ | 8：工具选择 | 能区分解释的观测量与工具覆盖边界 |

## 1. 解释器：追踪值怎样变成语法

**操作。** 从真实入口标出可控字段，再从 SQL、命令、模板、路径或解析 API 反查调用者；先连通调用，再逐变量核对实参、字段别名、返回值、包装器、异步消息与持久化。记录每次解码、规范化和上下文变化；调用链连通不等于该参数可传播。[污点方法][taint]

- 核对最后一个解释器及其参数语义：参数数组避免 shell 解释，但被调用程序仍可能把可控值当选项；绑定 SQL 值避免改变该占位处的 SQL 结构，但不证明资源授权。
- 读取净化函数实现、失败分支与使用点。HTML 文本编码不能直接保护脚本字符串；路径校验后再次解码、拼入新片段或改用另一个值，要重算保证。
- 不因函数无参数就停止反查：对象字段、共享状态、数据库和消息均可携带外部控制；反射／多态无法解析时列出具体断点。

**MyBatis 对照。** `WHERE name = #{name}` 在该位置绑定值；`WHERE name = '${name}'` 将文本纳入 SQL 语法。先核对实际 mapper、参数绑定与 JDBC 调用，不能只看接口签名。[专项来源][mybatis]

| 位置／构造 | 要继续读取什么 | 能区分的结论 |
| --- | --- | --- |
| `${sort}`、动态表／列名 | 字段名是否由服务端固定映射产生，校验后是否替换 | `created → created_at` 的封闭映射与自由 SQL 片段不同；只允许字母不证明有权读取该表 |
| `<if>`／`<choose>`／`<foreach>` | 分支条件、片段包含、每个元素的来源 | 默认分支安全不能覆盖可触发的拼接分支 |
| Provider、`apply`／`last`／排序 wrapper | 最后生成的 SQL、绑定参数及当前版本 API 语义 | builder 名称不保证参数化；已拼接模板与绑定值不同 |
| `#{value}` 写库后又读出拼接 | 谁能写该记录、哪个任务读取、何时进入新解释器 | 首次保存安全不消除二阶输入控制；纯服务端常量也不能臆造为用户输入 |

**下一步与界限。** 选一个可达分支，列出最终 SQL 模板与独立绑定值，或精确列出仍未解析的 wrapper；验证一个可控字段能否改变语法。只裁定这条路径与已读变体；“有 `${}`”或“用了 `#{}`”都不能裁定整个 mapper 安全性。
**决策点留板。** 保存入口→变换→最终参数的短证据链、最强拦截控制及未解析调用；二阶流程保留写入者、记录字段、读取动作和版本。

## 2. 授权：入口→角色／资源／动作矩阵

**操作。** 从实际注册路由、RPC、消息消费者、CLI 子命令或库的受信调用边界枚举动作；按资源归组，列出 create/read/list/update/delete，以及 copy、export、bulk、restore、异步任务等真实变体。矩阵写“控制在哪里及覆盖谁”，不只写“有／无注解”。[控制驱动来源][deep]

| 入口与动作 | 主体／对象对照 | 应读取的控制与观察 |
| --- | --- | --- |
| 文档 read／list／export | 所有者、同团队非成员、其他团队 | 单条读、列表过滤、导出查询是否采用相同资源策略 |
| 文档 update／delete／copy | 只读成员、编辑者、管理员 | 动作权限、源对象读取权、目标容器写入权分别在哪检查 |
| `bulkDelete(ids)` | 混合允许和禁止的虚构 ID | 是逐对象裁定、带权限谓词更新，还是只验证第一个对象；部分成功是否符合契约 |
| 分享 read／健康检查 | 匿名、有效分享令牌、撤销令牌 | 公开行为的产品契约、字段范围、令牌作用域与撤销语义 |

- 先查全局认证／授权 middleware、过滤器链、路由组继承、策略注册和执行顺序；再查 service、ORM scope、数据库行级策略及旁路入口。注解存在也要确认代理调用或实际挂载使其生效。
- 行级控制必须绑定同一主体与被操作对象：查询有 `tenantId` 只证明该谓词隔离的范围，不能自动证明团队内私有文档可读。数据库 RLS 还要核对连接身份、会话租户和绕过角色。
- create 检查目标父资源；update 检查字段权限与重归属；copy 同时检查源和目的；bulk／export 检查完整集合、分页、筛选和后台执行时继承的身份。
- 直接绑定 entity 时，追到字段最终是否被持久化及是否由服务端覆写。DTO 缺失但服务端强制设置角色，与客户端角色一路保存，是不同解释。
- 登录、注册、健康检查和按设计公开的分享页允许匿名；判断实际字段与动作是否超出公开契约。公开路由处理私有对象时仍需对象策略。

**下一步与界限。** 选择矩阵中两个仅权限或对象归属不同的调用，静态对照最终查询／写入条件；需运行时再用虚构主体观察允许与拒绝的差异。结论写清是角色、团队还是对象边界；read 与 delete 控制不同只是线索，不自动构成越权。
**决策点留板。** 保存策略依据、两种主体／对象、最终决策位置及绕过路径；未知的全局控制保持未知，不把“没在 handler 看见”记录为“没有控制”。

## 3. 响应：追到最终消费者，而非第一次设置头

**操作。** 文件名、上传 MIME、存储元数据和响应 API 要一起追；按真实执行顺序列出每次设置／删除头、写 body、重定向与流发送，再查当前框架版本的实现和返回途中 middleware。[Outline 实例][outline]

- 对照：先把类型设成安全值，随后调用根据文件名推断类型的 attachment helper，最终类型可能被覆盖；倒换顺序会改变结果。不能把早先的 MIME allowlist 当作最终响应证据。
- 同时检查最终 `Content-Type`、`Content-Disposition`、`nosniff`、CSP、来源域和具体使用方式。下载提示不必然阻止内容作为脚本子资源使用；顶层浏览与子资源加载需要分别推理。
- 追存储路径：本地存储经应用域返回，与对象存储／独立域返回，有不同的 Cookie、同源和策略边界；云部署与自托管不能直接共享结论。
- CSP 的 sandbox、脚本来源及 nonce 等约束可能阻断某种执行，也可能不覆盖另一种使用方式。看到 CSP 缺失不等于 XSS，看到 CSP 存在也不等于所有路径被保护。

**下一步与界限。** 先在源码形成“调用顺序→最终头→浏览器加载上下文”表；框架行为未明时设计最小 helper 对照，浏览器行为未明时设计虚构内容的本地观测。分别裁定头覆盖、脚本执行和账户影响，不能由第一个直接跳到最后一个。
**决策点留板。** 保存头的最后写入者、框架版本、存储／部署分支与阻断条件；Outline 是寻找同类语义的实例，不证明其他 Koa 应用有同样漏洞。

## 4. 状态、并发与配置：证明可行的时间线

**操作。** 写出受保护不变量、允许迁移、参与者与检查／提交时刻，再寻找重试、重复、乱序、撤销、取消和异常恢复路径。配置只围绕这条路径核对优先级、默认值、运行覆盖及最终生效值。[状态调查启发][deep]

- 订单只能领取一次：`读取未领取→发放→标记` 需要分析可交错窗口；`UPDATE ... WHERE claimed=false` 并以受影响行数决定发放，可能已把决策原子化。无锁不是证明。
- 给出可核对交错：A 读旧状态、B 读旧状态、A 执行、B 执行。核查隔离级别、唯一约束、条件更新、锁覆盖对象与提交时点，证明这些步骤能同时成立。
- 事务存在不保证外部副作用一起回滚；检查消息投递／支付调用在提交前后，以及幂等键的作用域、占位与完成状态。正常业务允许的重复编辑不直接等同于安全缺陷。
- 授权后排队执行：核查消费者是否重新校验撤销后的权限；明确契约要求检查入队时还是执行时，不能凭个人偏好认定撤销绕过。
- 文件 TOCTOU：检查路径后重新按名字打开，需要证明低权方能改动相应目录／链接；若使用同一受保护目录句柄或已打开对象，原先的替换设想可能失效。
- 对配置差异列明环境、启用条件和边界后果；开发专用入口不直接报为生产暴露。弱配置还要证明攻击者可到达对应服务和动作。

**下一步与界限。** 先用源码排除一个会阻止交错的机制；仍可行时设计限定步骤的调度／屏障对照，观察虚构资源的不变量。一次抢占失败只说明这次调度；理论窗口而无可控参与者时保留具体可行性未知。
**决策点留板。** 保存最短状态／交错序列、共享对象、有效约束与尚缺部署事实；静态路径证据和真实调度观察分开记录。

## 5. 原生 API：长度、所有权与生命周期

**操作。** 从文件、库 API、FFI、CLI 或消息解析入口追 `buffer + length` 契约，逐个核对类型宽度、符号转换、中间算术、实际容量、编码单位和终止符；再画对象获取、借用、转移、释放与回调使用顺序。[原生检查起点][native]

- 对照 `count * stride`：最终结果放入 `size_t` 不证明乘法先前未在窄类型溢出。核对运算发生的类型、分配大小与后续循环／复制采用的长度是否一致。
- 检查“元素数”和“字节数”、字符数与 UTF 编码长度、头长度与剩余缓冲区；`offset + len <= size` 还需排除加法溢出，边界样本要覆盖零、末尾及截断输入。
- 返回内部 view／裸指针后，检查容器扩容、临时对象销毁、异步回调和错误释放路径。智能指针名字不能证明共享所有权控制块正确，借用跨回调也不能默认有效。
- 核查调用方是否违反公开 API 前置条件：harness 伪造不允许的悬空指针，不证明正常调用者可触发；不可信长度经合法 API 到达越界，则需继续关联实际主体和宿主进程。

**下一步与界限。** 为一个边界表达式列出类型与取值区间，或为一个对象列出最后有效时刻和首次越界使用；必要时选择 ASan／UBSan 对应观测。内存错误、解析拒绝、宿主退出和代码执行是不同结论，不能由 crash 推出全部影响。
**决策点留板。** 保存 API 契约、长度等式／生命周期、调用者可控能力与最小观察；有效证据可为库调用输入、CLI 参数／文件、消息字节与诊断，不要求 HTTP 或 Burp 请求。

## 6. 依赖：版本告警与实际使用分开

**操作。** 交叉读取清单、锁文件、传递依赖、打包目录和装载配置，确认具体制品中的组件身份；再把公告的受影响版本、入口、特性和修复条件映射到实际调用。[Java 组件线索][java]；[Outline 的部署差异][outline]

- 声明范围包含旧版不证明锁定或装载旧版；版本字符串相同也可能有厂商回补、vendoring、shading 或私有补丁。定位修复逻辑与构建／发布映射，无法映射时明确未知。
- 组件存在但仅用于开发构建，与生产进程加载并暴露受影响功能不同；有版本告警但不可达，与可达的自写包装器绕过修复条件也不同。
- 无公告不代表无缺陷：框架实现、变更和修复差异仍可解释行为；不能因数据库无命中就停止已存在的源码路径调查。

**下一步与界限。** 选一条公告，给出“当前制品身份→实际函数→输入能力→公告触发条件”的对应表；缺制品身份时只判断已读源码或依赖声明，不声称当前部署已受影响。
**决策点留板。** 保存公告／修复版本、实际组件身份及可达条件；组件风险线索与应用边界结论分开，更新版本不能自动撤回所有关联问题。

## 7. 源码、反编译与缓存：先证明谱系

**操作。** 有对应源码优先读源码；缺关键实现时使用反编译阅读线索，并把原始 JAR／WAR／DLL／EXE 身份、内部类／程序集位置、工具版本／选项、引用集和输出映射保留下来。[Java][java]；[.NET][net]

- 源码提交不自动等于部署物；反编译行号只定位派生文本。关键分支、常量或异常路径不可信时，回到字节码／IL／原生反汇编及原始方法身份核对。
- 反混淆后的名称与文件是派生产物，跨程序集引用可能改变；保留原始→处理后映射，不把派生产物替换部署物执行。
- 缓存目录相同不证明可复用：比较原始输入内容指纹、工具／选项、引用集和成功清单；`partial` 只复用成功且身份匹配的条目。
- 失败、跳过、空输出、无法解析或旧缓存不是“没有入口／危险调用”。指出缺失类／方法与受影响调用链；入口程序集提取失败尤其不能作覆盖完成证据。

**下一步与界限。** 将一个关键派生方法映射到当前原始制品中的方法，核对决定性分支；不能映射时暂停该源码／部署等价判断，继续其他有身份依据的路径。
**决策点留板。** 保存谱系、成功／失败范围及其阻断的具体论断；提取成功是证据来源成熟度，不自动使漏洞成立，提取失败也不使漏洞为假。

## 8. 工具：只为一个精确未知量选择方法

先写一句可区分的问题与观察标准，例如“别名字段是否穿过 wrapper 到 SQL 文本”，而非“跑工具找漏洞”。下表是选择规则；具体目标运行按 [执行与验证](execution.md)，本页不授权安装或执行。

| 未知量 | 方法与检查动作 | 观察如何限制结论 |
| --- | --- | --- |
| 同类调用在哪里、控制是否传播 | 静态语义／污点查询；抽查真实 source、sink、字段和跨函数 summary | 列出已知入口／危险调用是否进入模型；遗漏 wrapper 或错误净化模型时，零命中无排除力 |
| 某条路径是否发生越界／未定义行为 | 最小输入配合 ASan／适合的 UBSan 检查 | 核对目标模块确被相应检测插桩；诊断要归属目标而非 harness，且不直接证明部署影响 |
| 格式／状态输入的哪些组合破坏不变量 | fuzz；明确解析结果、资源约束或状态不变量作为 oracle | 看目标分支覆盖，不能只看执行次数；无 crash 不排除授权、逻辑或未覆盖的错误 |
| 两个消费者／版本是否解释不同 | differential 对照；固定相同输入、配置、状态与比较字段 | 差异本身不是漏洞，需指定契约、哪方违反它及安全边界；双方也可能同错 |

- **查询校准：** 用手读已知路径核对 source／sink 枚举、参数位置、返回值／字段 summary 与有效 barrier；验证允许路径与被阻断路径能区分，再扩展变体。[模型扩展][queries]
- **Harness 校准：** 初始化真实必要状态，保留目标语义；核对空／短输入、长度与所有权合法性、每轮状态重置和回调结束。只测底层 parser 不代表注册／授权层已覆盖。[编写 harness][harness]
- **覆盖校准：** 看目标分支是否越过 magic、校验和、状态门槛；用合法种子／结构化输入针对缺口。补丁绕过门槛时单独记录，不能把改变后的行为当成原程序行为。[覆盖分析][coverage]
- **检测校准：** sanitizer 是运行时错误检测器，与输入净化器不同；ASan、UBSan 和覆盖插桩各有范围。检测兼容性或资源限制无法满足时回到静态问题，不照抄来源中放宽限制的建议。[ASan][asan]

**下一步与界限。** 每次仅定义能减少当前未知的最小查询／输入对照／harness 和可接受观测；实际结果分别写原始观察、解释与未覆盖范围。工具失败、数据库缺失或编译失败只证明检查未完成。
**决策点留板。** 在改变结论、排除解释或发现覆盖断点时保存证据，使用现有 `supports`／`contradicts`；必要条件用 `depends-on`。关系不自动传播真假，证据成熟度、裁定与影响分开，未知可继续保留。
