# pinwhy-code-audit

独立的代码安全审计场景包。用具体假说、控制分析和验证反馈推进调查，用现有黑板保留可恢复的事实、解释与未决问题；底座、通用 Skill、查看器和安装器保持原样。

## 2.0 的重点

- 从“追踪、证伪”的原则落实到下一项动作：读取哪个保证的建立者，哪种结果能区分竞争解释，什么时候需要改实验而非撤回候选。
- 按问题选技术：解释器与二次使用、角色／资源／动作矩阵、框架调用后的最终响应、状态交错、原生长度／所有权和产物谱系。
- 变体从已知实例校准，逐轴扩展并解释安全反例；差分比较不变量、控制迁移、调用方和失败副作用。
- 将环境失败、未到达、有效负结果和有效正结果分开；查询模型、harness、构建模式和实际交付物决定证据边界。
- 黑板只记录值得恢复的转折，不要求把每个模板字段拆成节点，不以发现数、边数或图形状衡量审计。

## 使用

入口：[SKILL.md](SKILL.md)。例如：

> 使用 pinwhy-code-audit 审查这个模块的导出和批量操作权限。复用现有黑板，先核对真实控制，再追可能绕过的路径；默认只读。

> 这个修复移除了旧校验，检查保证是否迁移到了共享层、哪些调用者仍受保护，并把依据记到黑板。

> 继续黑板里的调查，区分上次实验没到达目标和真正的反证，找下一项能改变判断的检查。

明确要求审计使用黑板即授权相应记录；不代表安装、升级、启动服务、发布材料或执行线上测试。目标运行需要额外的实际隔离能力，见 [执行参考](references/execution.md)。

## 加载与分发

本目录是该场景 Skill 的唯一源。按宿主支持的 Skill 机制加载完整目录，包括 `references/`、`assets/`、`agents/` 和 `evals/`，不要只复制入口。项目级目录可为 `.agents/skills/pinwhy-code-audit/` 或 `.claude/skills/pinwhy-code-audit/`；安装前保留用户已有内容。

现有 `pinwhy skill install` 安装的是通用 pinwhy，不假设它分发本场景包，也不为此修改安装器。CLI 通过 PATH 或已确认的稳定安装路径定位，不内嵌 CLI，不把开发副本用于真实项目记录，不保存个人绝对路径。

本次交付为场景源包，未自动安装进当前宿主。文件存在、宿主加载和自动触发分别验证。

## 维护

先固定一个实际失败的调查场景，再修改方法并对照旧版本。格式合法、命令可运行、更多节点与更长报告，都不能单独证明审计更好。效果只按实际场景报告；不能复制旧版本通过数充当本轮验证。
