# 场景评估

评估检验判断与调查推进，不以图形、记录数量或报告长度计分。全部输入独立编写且为合成材料；不执行目标 fixture，不安装依赖，不访问服务。

## 输入与隔离

[evals.json](evals.json) 中用例 1–3 是初版基本场景；其 [1.0 结果](RESULTS-v1.md) 保留历史范围，不沿用成 2.0 已运行证据。用例 4–6 增加框架后续行为、对象授权、存储后二次解释、查询模型缺口和中断调查。

每次受评任务使用全新上下文、独立板根和输出。2.0 的对照是改动前保留的完整 1.0 快照；固定相同模型配置、输入、工具、权限和用户提示，仅改变所读 Skill 包。受评者只得到 prompt、源码和自己的板根，不能读取预期答案、断言、另一组输出或本文件。

不按节点数量、是否拆成多个 finding、具体标题、关系数量或原文措辞判分。一份聚合记录保留多个可复核实例，与显式多节点映射，都可正确。

## 三个深入场景

- **4：操作与最终响应。** 阅读实际路由注册、共享策略、处理器、响应 helper、发送顺序和当前配置，分别判断真实对象越权、有效保护及未成立的扩大影响。
- **5：变体与模型。** 从已修复的历史实例核对当前保证，追踪先存储后解释的跨函数路径；判断已有扫描的 source/sink/summary 是否覆盖这些路径。
- **6：中断调查。** 协调者在新板导入 [seed.jsonl](fixtures/investigation/seed.jsonl)，使用实际 refs 建检查点。受评者只得到当前源码、提供的历史日志和板根，恢复竞争解释后分别核查，不能把未到达的实验当反证。

上述说明和 assertions 是评估者材料，不复制进受评任务。输入中的合成历史日志是提供的记录，不是本轮执行观察；不得给 agent 伪造的实时工具返回。

## 观察与判分

从实际工具调用、报告、黑板公开 CLI 读回结果核查每条断言，保存通过／未通过与具体依据。先分别评分再比较两组，尽可能隐藏组名；不能因为希望 2.0 有收益就放宽标准。若两组均通过，报告该项没有区分出额外收益。

关注有意义的结果：是否找出真实机制和受影响路径；是否核对真实控制和安全反例；未知是否被正确保留；环境与到达性如何影响结论；交接是否让新会话知道下一项能改变判断的检查。

将运行时间、读取范围与记录量作为成本观察，不把一次耗时或更多节点直接解释为效率或质量。少量单次合成样本不支持真实召回率、误报率或显著性主张。

## CLI 与包验证

在新合成板验证现有 CLI：禁止误初始化、批量 check 不写入、正式写入、同请求重试、回执、显式反证和未知态、预算省略、实际报告映射与筛选导出。只使用 capabilities 声明的增强，缺少 asOf 等能力时使用普通恢复，不升级底座。

另外检查 Skill 元数据、全部本地链接和自包含资源、公开内容、完整打包清单以及相关仓库检查。它们证明包能被读取和命令可用，不能代替实际调查场景。

## 触发与执行限制

`trigger_queries` 是初始正反例；只有在真实宿主注册并观察自动加载后，才能报告触发率。显式加载不能证明自动触发。

本轮源审计场景不执行目标，所以没有运行验证沙箱的实测证据。原生编译、浏览器、真实部署、长时间与多模型长期审计收益只按实际运行的额外场景声明。

实际结果记录在 [当前验证结果](RESULTS.md)，历史结果保留原版本范围。重新评估时不能把旧检查或未执行的观察算成新证据。
