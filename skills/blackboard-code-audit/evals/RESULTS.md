# 2.0 验证结果

本轮把七处资料落实到独立审计场景的调查方法、技术配方、实验解释与可恢复回传。新旧版本在本次三个深入合成场景中都满足预设断言，**没有证明 2.0 提升了检出率或降低了误报率**。方法更具体是可直接检查的文档变化，效果主张仍受下列实测范围限制。

## 对照设计

保留改动前完整的 1.0 包快照。用例 4–6 各启动两个全新调查任务，分别显式读取 1.0 与 2.0；输入、公共 CLI、工具权限和任务提示一致，板根、署名与输出隔离。六个任务使用同一宿主默认 task 配置，未指定单次模型覆盖；没有固定提供方模型版本，也没有重复采样。

受评者不能读取答案、断言、其他板、另一版本或其他输出。用例 6 由协调者事先导入相同合成现场并创建实际引用的检查点；受评者只得到板根、当前源码与提供的历史记录。

协调者实际读取六份报告，并用公开 `ls --all`、`context` 读回六块板的节点、关系和检查点；用于判分的恢复没有省略。隐藏方法路径与组名后，由独立、无工具模型逐项辅助判分，再对照源输入及读回记录核查。不是自动触发测试，也不是完全双盲研究。

## 场景结果

| 场景 | 1.0 通过断言 | 2.0 通过断言 | 本轮节点数：1.0 / 2.0 |

| 5：存储后二次解释与查询模型 | 6 / 6 | 6 / 6 | 13 / 6 |

两组都识别了导出只检查团队、缺少对象权限的机制；核对了后续 helper 覆盖安全 MIME，同时保留浏览器影响未知。两组都区分已修复的直接入口与仍存在的二阶 SQL 路径，覆盖手动／调度两个消费者，并指出现有扫描的明确模型缺口。恢复场景都以完整长度检查反驳 H1，保留 H2 的条件化越界机制和交付物配置未知，没有把历史 exit 78 当作有效漏洞反证。

2.0 的变体输出实际采用了精确种子、扩大包装调用、再追存储来源的分步检查；恢复输出明确区分模块未编入、断言保留和断言移除。1.0 同样达成这些场景的核心结论，因此不能将这种表达差异写成额外检出收益。

节点数仅描述这一轮的聚合方式；少建节点、较短报告或单次耗时都不直接计分，也不证明普遍节省成本。原三项基本用例没有在本轮重跑，其 [1.0 历史结果](RESULTS-v1.md) 不计为 2.0 已运行证据。

## 实际 CLI 验证

开发 CLI 的 13 项行为检查通过：批量预检不改节点、正式导入、同请求重试保持节点身份、已提交回执与实际 refs、筛选当前确认项、显式反证、未知不隐含确认／严重度、多实例报告映射、预算省略提示、增量与历史投影、显式编辑历史、筛选 Markdown 导出、超限证据拒绝与缺板 no-init 保护。相关导入、回执和重试合并在同一行为检查中，检查项数不是命令数。

临时检查器最初错误地从 `search.items[].status` 读取状态，修正为公开投影的 `items[].node.status` 后通过；没有修改 CLI 或重做已成功导入。

另外使用已安装稳定 CLI 在新合成板实际验证 6 项：预检不写入、同请求 refs 一致、回执提交、完整普通恢复、确认项筛选、反驳与未知分开。该安装没有声明 `asOf`，本轮按能力使用普通恢复，没有升级、重装或增加底座分支。

以上均为可信 CLI 操作独立合成板，不是运行审计目标，不证明执行沙箱已经可用。

## 独立包审阅

独立 reviewer 阅读入口、工作循环、调查与技术参考、执行边界、记录、CLI、来源和回传模板，未发现有证据的实质性问题。该结论限于本次文件和所述检查，不等于包内所有方法都已在真实目标运行。

## 范围与限制

- 六次为单次、小规模、只读合成调查；没有真实项目召回率、误报率、统计显著性、跨模型或长期审计收益证据。
- 没有执行目标、浏览器、原生编译、真实数据库或扫描器；不声称上述执行与隔离路径得到实测。
- 没有将源包安装进当前宿主，也没有验证真实宿主自动触发率。显式加载与自动发现分别判断。
- 模型对聚合统计的附带解释不作为裁定依据；以具体节点和证据为准。本轮没有为处理这种解释修改统计或投影。
- 全部源包改动限制在 `skills/blackboard-code-audit/`；合成板、1.0 快照、报告、CLI 观察和辅助判分只保留在私有验证目录。没有改内核、通用 Skill、查看器、安装器或宿主配置。

来源与规则取舍见 [七处资料的归纳](../references/research.md)，输入与断言见 [评估定义](evals.json)。后续维护应优先增加有真实失败依据的调查，而不是为制造新版胜出而反复改题或挑结果。
