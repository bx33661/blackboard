# 调查事项与回传

仅在复杂或并行事项中使用；简单问题可直接写入节点 detail。填写实际已知内容，未知就写未知，不为填模板补造事实。它是临时回传，导入后以黑板为恢复入口。

```text
事项：本次要回答的具体安全问题。
对象：源码／产物版本、相关内容身份、实际位置、范围与排除项。
主体与边界：谁控制什么输入／动作，哪项保证保护谁的资源。

已知事实：逐项引用实际代码位置或已有证据；区分本轮读取、历史记录和外部契约。
竞争解释：
  H1：候选机制，以及支持它的事实。
  H2：最有力的其他解释／防护，以及需要什么依据才能成立。
  没有真实竞争解释时写没有，不凑假说。

判别检查：
  实际读取／查询／实验及其目的。
  预测：哪些结果分别支持或否定哪个解释。
  观察：实际看到什么；本轮亲自执行／历史结果／未执行分开。
  到达性：环境未就绪／未到达／有效负结果／有效正结果／纯源码判断。
  限制：移除了哪些前提、缺少哪些调用方／模式／产物；不能据此推出什么。

当前裁定：candidate／confirmed／needs_validation／rejected；对应主张与理由。
未决事实：精确需要哪项证据；它是否能在现有源码继续查到。
下一项区分性检查：读哪里或观察什么、为什么这会改变判断。
同源与组合：已有实例、排除的对照、变体搜索边界与真正兼容的依赖。
覆盖：实际回答的入口／操作／分支与未覆盖范围。

记录引用：实际节点与私有证据位置；写入尚未完成时明确未保存。
修复建议：失效的保证与最小有效改动，未知机制不捏造修复。
```

H1、H2、检查编号只是事项内的局部名称，不是黑板 ID；批量导入的 `$ref` 只在 ID 字段引用，正文不会自动插值。需要关系时使用实际返回 ID，证据支持／反驳论断；假说之间不因竞争就自动互为反证。

已知事实、当前解释或验证结果发生变化时更新相应记录；交接保留被否定解释和检查范围。不要把所有字段各拆成节点，也不要为安全对照先创建假的 finding。
